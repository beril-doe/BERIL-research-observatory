# Reproducible Data Provenance

Reproducible data provenance is the discipline of tracking where a dataset came from, how current it is, how it was transformed, and how an analysis built on it can be independently re-executed and audited. The BERDL corpus speaks unusually directly to this topic because it is not just a set of biological findings but a lakehouse platform under active migration, staffed by multiple independent projects that repeatedly rediscovered the same category of failure: results computed on a resource whose identity, freshness, or transformation history was not explicit. The corpus therefore contains both a systematic audit of the platform's provenance gaps and a set of biological re-analyses that show, empirically, how much a conclusion can shift when provenance and sensitivity checks are done properly versus skipped.

## What the Corpus Shows

**Provenance cannot be inferred from a name.** The NMDC context audit is the corpus's clearest demonstration that shared substrings, tenant placement, and catalog prefixes are unreliable proxies for data identity. Of 20 database names containing `nmdc`, only seven were real, maintained resources, spanning three tenants and six provenance classes [src: nmdc_context_audit]. The genuine NMDC biosample table held 16,640 samples, while a co-hosted, similarly named NCBI mirror held 51,711,888 biosamples and 756,112,544 attribute rows — a roughly 3,000-fold scale mismatch invisible to name-based selection [src: nmdc_context_audit]. `kbase.nmdc_neon` turned out to belong to NEON, not NMDC, at all [src: nmdc_context_audit]. This case study anchors [[concepts/provenance-aware-data-discovery]] and argues that authority, scope, and scale must be surfaced as discovery metadata, not inferred.

**Currency is a distinct, measurable axis of provenance.** Iceberg's `.snapshots.committed_at` field is the only available freshness signal in the audited environment, and it varied by roughly four months across resources labeled `nmdc`: the freshest, `kbase.nmdc_mags` and `kbase.nmdc_neon`, were last committed 2026-07-02, while `nmdc.ncbi_biosamples` lagged at 2026-03-09 [src: nmdc_context_audit]. Freshness does not track tenant or authority — the freshest NMDC-related resource sat outside the `nmdc` tenant entirely — so [[concepts/data-currency]] must be checked independently of provenance and scope, and both must be checked before selecting a resource for analysis, as [[concepts/evidence-triangulation]] argues more generally.

**Executable provenance is as important as data provenance.** [[concepts/computational-reproducibility]] extends the same logic to the analysis layer: BERDL's live migration from underscore Delta namespaces to dotted Iceberg namespaces means code must resolve tables at execution time rather than hard-coding a convention, and the resolved address and tenant should be recorded alongside results [src: pitfalls]. Notebooks referenced in a project's documentation must exist in Git history as executable artifacts, not just as interactive session outputs — ENIGMA's NB08–NB10 initially existed only as the latter, leaving a provenance gap between the "real" analysis and its reconstructed rerun [src: pitfalls]. Committing notebooks with empty output cells, or using `nbconvert --inplace` in ways that silently produce zero outputs, breaks the audit trail just as thoroughly as losing the code itself [src: pitfalls].

**Identifier and schema resolution is itself a provenance record.** Cross-database joins are a recurring failure point: short ENIGMA strain names produced 12 incorrect genus linkages among 32 pangenome linkages, and MetaPhlAn3 cross-cohort integration needed an explicit synonymy layer to avoid manufacturing abundance contrasts from taxonomy-naming drift alone [src: pitfalls]. The corpus's prescription — record the original and canonical identifiers, the database/taxonomy version, the matching rule, and counts of matched/unmatched/ambiguous records — makes identifier resolution a documented, auditable step rather than an invisible cleaning operation, linking to [[concepts/identifier-resolution-and-crosswalks]] and [[concepts/pangenome-integration]].

**Scale-aware engineering is a reproducibility requirement, not an optimization detail.** [[concepts/scalable-spark-data-analysis]] shows that BERDL's size (e.g., billion-row `gene` and `gene_genecluster_junction` tables [src: pitfalls]) means an analysis that is correct in principle can fail to complete, or complete non-deterministically, if Spark session state, broadcast-join configuration, or JupyterHub's 17–25 minute idle kill are not accounted for [src: pitfalls]. A run that silently dies, or that hangs for 17+ minutes because automatic broadcast joins were disabled, is not reproducible even if the code is version-controlled, because its execution context is unrecorded and unrecoverable [src: pitfalls].

**Re-analysis is the sharpest test of provenance discipline, and the corpus provides its own natural experiment.** [[concepts/plant-compartment-filtering]] shows a Phase 1 compartment effect of PERMANOVA R² = 0.527 collapsing to R² = 0.071 once a broader marker panel's uneven taxonomic sampling was corrected — an 86% reduction traced to a small number of dominant clades rather than to a genuine community-wide signal [src: plant_microbiome_ecotypes]. [[concepts/host-specific-microbial-adaptation]] shows the mirror-image risk: only 5 of 17 testable species passed corrected subclade tests for host association, and 47 of 65 candidate species lacked the phylogenetic data needed to test the claim at all [src: plant_microbiome_ecotypes], so an unresolved-provenance gap (missing tree data) directly bounds what can be concluded. Both cases demonstrate the corpus's broader argument in [[concepts/computational-reproducibility]] that sensitivity analyses must be independently constructed and their diagnostic history preserved, not just their preferred final numbers.

## Tensions and Caveats

The corpus does not present provenance discipline as costless or fully resolved. The audit itself concedes that co-hosting external and derived resources under a shared tenant is not always harmful — the NCBI mirror gains attribute harmonization and the Arkin derivative gains embeddings — so the fix is explicit metadata, not removal, a genuine design tension within [[concepts/provenance-aware-data-discovery]] [src: nmdc_context_audit]. The audit also admits its central claim, that overloaded naming causes suboptimal resource selection, is inferred from gap analysis rather than directly observed user behavior [src: nmdc_context_audit].

More broadly, several promoted conflicts show that even carefully provenance-tracked analyses can disagree once coverage, mapping resolution, or phylogeny are varied. [[conflicts/conflict--enigma_contamination_functional_potential--euk_in_prok_correlates--soil_frontier_genomics]] shows coverage-adjusted exploratory models detecting signal that predeclared, confirmatory, or cross-study-holdout tests then fail to reproduce — precisely the sensitivity-analysis-independence problem [[concepts/computational-reproducibility]] warns about. [[conflicts/conflict--bacdive_metal_validation--clay_confined_subsurface--ecotype_env_reanalysis]] shows two analyses using related environmental-embedding provenance (AlphaEarth-derived geography) reaching opposite conclusions about whether geography predicts gene content, illustrating that a shared data source does not guarantee shared conclusions. [[conflicts/conflict--bacdive_phenotype_metal_tolerance--ecotype_analysis--ecotype_env_reanalysis]] shows mechanistic trait claims repeatedly collapsing under phylogenetic controls, the same confound structure documented within [[concepts/host-specific-microbial-adaptation]] and [[concepts/plant-compartment-filtering]]. The general caveat: passing a provenance and reproducibility checklist establishes that a result *can* be audited and rerun — it does not by itself establish that the result is biologically robust to resolution, coverage, or phylogenetic confounding.
